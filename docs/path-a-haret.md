# Путь A — HaRET: pmOS без единой записи в NAND

Windows Mobile не трогается физически: HaRET — обычное .exe-приложение WinMo, которое
выключает MMU, кладёт в RAM ядро с SD-карты и передаёт ему управление. Откат = удалить
файлы с карты.

## Что уже есть на аппарате (проверено)

HaRET установлен: `D:\ICS\` — рабочая SD-сборка Android ICS.
`haret.exe` (dec.2010), `clrcad.exe`, `zImage`, `initrd.gz`, `system.ext4`, `data.ext4`.

`D:\ICS\STARTUP.TXT` даёт параметры, проверенные на этом конкретном телефоне:

    set mtype   2524          # = MACH_HTCLEO, совпало с mach-types форка ядра
    set ramaddr 0x11800000    # совпало с deviceinfo_flash_offset_base
    set ramsize 0x1e400000    # <- ЭТО подбирать не нужно, значение рабочее
    set initrd_offset 0x00a00000

Готовый `startup.txt` для pmOS лежит в [../out/pmos-startup.txt](../out/pmos-startup.txt).
Отличия от ICS-варианта:
- `cmdline` другой — у pmOS свой initramfs, он ищет корень по метке раздела `pmOS_root`,
  а не по `rel_path`/`root=`. Взят штатный `kernel-cmdline.conf` устройства
  (`no_console_suspend=1 wire.search_count=5`) плюс `console=tty0` и
  `PMOS_NO_OUTPUT_REDIRECT` (вывод initramfs на экран — на первых загрузках нужен).
- `initrd_offset` поднят с `0x00a00000` до `0x01000000` (= `deviceinfo_flash_offset_ramdisk`):
  initramfs pmOS заметно крупнее андроидного и на 10 МБ рискует налезть на распакованное
  ядро. Если не грузится — вернуть `0x00a00000`, затем попробовать `0x01800000`.

## Проблема: карте нужен ext4-раздел

Сейчас SD — **один FAT32-раздел на 29,7 ГБ** (MBR), занято 2,6 ГБ.
Android ICS-сборка живёт файлами внутри `\ICS\`, отдельный раздел ей не нужен, а
postmarketOS так не умеет: его initramfs ищет **раздел с меткой `pmOS_root`**.

Значит, карту надо переразметить. Данные сохраняются через бэкап → восстановление.
Целевая раскладка:

| Раздел | ФС | Метка | Размер | Зачем |
|---|---|---|---|---|
| p1 | FAT32 | — | ~8 ГБ | видит WinMo: `\ICS\`, `\PMOS\`, ваши файлы |
| p2 | ext2 | `pmOS_boot` | 256 МБ | /boot (HaRET его не читает, но pmOS ожидает) |
| p3 | ext4 | `pmOS_root` | остальное | корень postmarketOS |

WinMo монтирует только первый раздел — p2/p3 он просто не увидит, это нормально.
`\ICS\` после восстановления продолжит работать как раньше.

**Альтернатива без риска:** взять вторую SD-карту под pmOS и не трогать эту вообще.
Если карта есть — так и сделайте, тогда шаг «бэкап/восстановление» отпадает.

## Порядок

### 1. Бэкап (Windows, уже сделан)

`C:\Projects\HTC-HD2-T8585\backup\sdcard\` — полная копия карты.
Проверить, что `backup\sdcard\ICS\` на месте, **до** переразметки.

### 2. Сборка (Linux-машина)

    ./scripts/build-pmos.sh          # init (vendor: htc, codename: leo) + сборка ядра

В `pmbootstrap init`: htc-leo архивирован, в списке его нет — вводить вручную.
UI: `console` для первого запуска, дальше `xfce4` или `mate` (3D нет, Phosh/Plasma не поедут).

Затем собрать образы **раздельно**, не на карту целиком:

    pmbootstrap install --split

Получатся `htc-leo-boot.img` и `htc-leo-root.img` (пути покажет сам pmbootstrap).
`--sdcard=/dev/sdX` здесь использовать нельзя — он затрёт весь диск вместе с FAT32 и `\ICS\`.

### 3. Переразметка карты (Linux)

    ./scripts/prepare-sdcard.sh /dev/sdX

Скрипт создаёт раскладку из таблицы выше и заливает в неё образы. Данные с карты он
не восстанавливает — файлы вернёте из бэкапа на p1 обычным копированием.

### 4. Payload для HaRET (Linux)

    ./scripts/make-haret-payload.sh out/PMOS

### 5. Разложить на карте

На p1 (FAT32):
- вернуть содержимое бэкапа, включая `\ICS\`;
- создать `\PMOS\` и положить туда `zImage`, `initrd.gz`, `startup.txt` из `out/PMOS`,
  плюс копии `haret.exe` и `clrcad.exe` из `\ICS\`.

### 6. Запуск

WinMo → File Explorer → `\Storage Card\PMOS\` → `clrcad.exe`, затем `haret.exe` → Run.

Меню выбора ОС нет: `\ICS\haret.exe` грузит Android, `\PMOS\haret.exe` — postmarketOS,
выключение и старт телефона возвращают Windows Mobile. Для нормального меню — [путь B](path-b-magldr.md).

## Если не грузится

- Чёрный экран сразу после HaRET → `initrd_offset` (см. выше), затем `ramsize`.
- Ядро стартует, паника «no root» → метка `pmOS_root` не проставилась на p3:
  `e2label /dev/sdX3 pmOS_root`. Проверьте, что телефон видит карту как `mmcblk0`.
- Зависание без вывода → сначала запускайте `clrcad.exe` (глушит звуковой драйвер,
  классический источник зависаний HaRET на HD2).
- Нет вывода вообще → в `cmdline` добавить `earlyprintk`.

Историческая справка: так на HD2 грузили Android в 2010–2011, механизм штатный.
Именно с postmarketOS связка публично не подтверждена — вики pmOS называет HaRET
«не лучшим выбором». Но цена ошибки нулевая: NAND не пишется.

## Почему карта готовится образом, а не напрямую из WSL

WSL2 к этой карте не пускают — проверено, а не предположено:

- `wsl --mount \.\PHYSICALDRIVE1 --bare` → `Wsl/Service/AttachDisk/HCS/0x8007000f`.
  Passthrough диска в WSL2 делает Hyper-V, а он не отдаёт носители со сменным медиа
  (`MediaType: Removable Media`). Явный перевод диска в Offline перед монтированием
  не помогает — проверено.
- Через карту в USB-кардридере то же самое. Сначала карта вообще была видна как
  `USB\VID_0BB4&PID_0FFD` — это сам HD2 в режиме USB-накопителя (0BB4 = HTC),
  а не кардридер. Перенос карты во встроенный слот
  (`BayHubTech Integrated MMC/SD`, шина SD) сменил шину, но не тип носителя.
- usbipd тоже не выход: в ядре WSL2 **нет драйвера USB-накопителей вообще**.
  `CONFIG_USB_STORAGE` отсутствует, каталог модулей `usb/storage` пуст — есть только
  `USBIP_VHCI` и `BLK_DEV_SD`. Понадобилось бы своё ядро WSL.

Поэтому карта готовится так: `scripts/wsl-build-image.sh` собирает **готовый образ в
файле** через loop-устройство (физические диски не затрагиваются), а на карту он
пишется обычным писателем образов из Windows.

### Раскладка образа (12,5 ГиБ)

| Раздел | ФС | Метка | Размер | Содержимое |
|---|---|---|---|---|
| p1 | FAT32 | `LEO` | 8 ГиБ | `\PMOS\` уже внутри; сюда же вернутся `\ICS\` и файлы |
| p2 | ext2 | `pmOS_boot` | 512 МиБ | `vmlinuz`, `initramfs`, `boot.img` |
| p3 | ext4 | `pmOS_root` | 4 ГиБ | postmarketOS edge, 3,3 ГБ свободно |

Образ намеренно меньше карты (12,5 из 29,7 ГБ): писать 30 ГБ ради пустого места
бессмысленно. Оставшиеся ~17 ГБ остаются неразмеченными; отдать их под данные можно
позже с самого телефона (`parted` + `resize2fs` в pmOS) — Windows расширять FAT32 и
ext4 не умеет.

### Запись

Образ: `out/htc-leo-sdcard.img`. Писать **Rufus в режиме DD** или balenaEtcher —
обычным инструментом, целиком на физический диск карты, не «на раздел».
Перед записью диск должен быть Online: `Set-Disk -Number 1 -IsOffline $false`
(от администратора) — неудачные попытки `wsl --mount` оставляют его в Offline.

После записи `\ICS\` и пользовательские файлы возвращаются на p1 из `backup/sdcard/`
обычным копированием из Windows.

### Запись образа: почему нужны две команды, а не одна

Прямая запись `dd` на карту под Windows отбивается с `Input/output error`, пока на
диске существует распознанный раздел: Windows защищает его сектора, а `dd` из MSYS
не умеет брать блокировку тома (`FSCTL_LOCK_VOLUME`). Проверено на практике.

`mountvol D: /P` не помогает — буква снимается, но раздел остаётся распознанным.
`Set-Disk -IsOffline $true` тоже не вариант: `Removable media cannot be set to offline`,
сменные носители Windows в Offline не переводит в принципе. Это же, кстати,
окончательно объясняет провал `wsl --mount`: Hyper-V требует диск в Offline, а карта
туда не переводится.

Поэтому сначала убирается таблица разделов, и только потом идёт запись.
PowerShell **от администратора**:

    Clear-Disk -Number 1 -RemoveData -Confirm:$false

Git Bash **от администратора**:

    dd if=/c/Projects/HTC-HD2-T8585/out/htc-leo-sdcard.img of=/dev/sdb bs=4M conv=fsync status=progress

Номер диска сверить заранее: `Get-Disk` — нужен SDHC на 29,72 ГБ, шина SD.
Системный NVMe на 477 ГБ — это диск 0, его трогать нельзя.
После записи Windows подхватит FAT32-раздел образа как новый том.
